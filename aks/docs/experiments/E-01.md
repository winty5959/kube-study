## Purpose and expected behavior

Delete one API Pod while at least two replicas are Ready. Kubernetes must replace
the Pod, and API requests routed through the stable Traefik service must continue
to return HTTP 200.

## Preconditions

Before the experiment, `root-dev` and `album-dev` were Synced/Healthy, the API HPA
minimum was one, and the API PDB required one available Pod. Automated sync was
paused on both Applications so Argo CD could not undo the temporary HPA minimum.
The API HPA minimum was changed to two; it reported two replicas and the PDB
allowed one disruption.

## Procedure and observations

The request path was a port-forward to the stable Traefik service, with the dev
host header. This keeps the local tunnel independent of the API Pod being deleted.
The initial attempt used a direct API Service port-forward; Kubernetes bound it
to the selected Pod, so deleting that Pod ended the local tunnel. Its failed local
requests were excluded from the acceptance result and the request path was changed
to Traefik before repeating the experiment.

```sh
kubectl -n ingress-system port-forward svc/traefik 18080:80
kubectl -n argocd patch application root-dev --type=json \
  -p='[{"op":"remove","path":"/spec/syncPolicy/automated"}]'
kubectl -n argocd patch application album-dev --type=json \
  -p='[{"op":"remove","path":"/spec/syncPolicy/automated"}]'
kubectl -n album-dev patch hpa api --type=merge -p='{"spec":{"minReplicas":2}}'
curl -H 'Host: album.aks.localhost' http://127.0.0.1:18080/api/photos
kubectl -n album-dev delete pod "$API_POD" --wait=true --timeout=60s
curl -H 'Host: album.aks.localhost' http://127.0.0.1:18080/api/photos
kubectl -n album-dev patch hpa api --type=merge -p='{"spec":{"minReplicas":1}}'
kubectl apply -f aks/argocd/root-dev.yaml
```

The actual request loop hid response bodies and counted status codes only. It sent
five baseline requests before deleting Pod `api-679bb59678-b5clv`, then 30 requests
during replacement. All 30 requests returned HTTP 200. The API Deployment returned
to two Ready replicas. The HPA minimum was restored to one and Argo automation was
restored; `root-dev` and `album-dev` were Synced/Healthy with automated sync enabled.

## Recovery

No application data was written or changed. The API HPA minimum returned to one;
the Deployment was under normal HPA control. No Git manifest changed. The temporary
root/child sync pause was removed by reapplying `aks/argocd/root-dev.yaml` and
waiting for the parent and child Applications to become Synced/Healthy.

## Limits

This validates short GET requests through the in-cluster ingress service during
one Pod deletion. It does not establish long-lived connection behavior, node-loss
availability, or a zero-error guarantee for uploads.
