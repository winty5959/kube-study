## Purpose and expected behavior

Supply an invalid database hostname to the PreSync migration gate. The
migration Job should fail before any Sync-phase workload is created, while the
existing dev application and data PVCs remain available.

## Preconditions

The AKS A8 GitOps smoke run had already tested this gate with a temporary
`migration-gate-probe` Argo Application, a unique `gate-` resource prefix, and
an invalid database host. The test used the AKS API migration image. This
record reuses that run instead of repeating the isolated failure.

## Procedure and observations

The temporary Application's `gate-db-migrate` PreSync Job failed with a host
resolution error. Its Sync-phase workload resources were not created. At the
same time, the real `album-dev` application was Synced/Healthy; its API was
1/1, frontend 2/2, PostgreSQL/Redis/MinIO each 1/1, and all three PVCs remained
Bound.

| Observation | Evidence |
|---|---|
| Invalid database host rejected in PreSync | [A8 GitOps smoke evidence](../../../.omo/evidence/aks-implementation/A8-gitops-smoke.txt) |
| No Sync-phase workloads created by the temporary Application | A8 Application resource result lists only the failed `gate-db-migrate` Job |
| Existing album-dev and its data services remained healthy | A8 workload and PVC state table |

## Recovery

The temporary Argo Application and failed gate Job were removed after the
failure was recorded. The real dev application, three data StatefulSets, and
PVCs were not changed by the gate test. This is a recorded AKS run from A8; it
was not repeated during A13.

## Limits

The gate rejects a hostname that cannot resolve. It does not test permission
errors, malformed SQL against a running database, or every migration rollback
case. The exact wall-clock time was not saved by the A8 recorder.
