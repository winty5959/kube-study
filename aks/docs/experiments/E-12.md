## Purpose and expected behavior

Change a Git-managed Deployment field directly in the cluster and verify that
the automated Argo CD self-heal returns it to Git. Do not alter the replica
count, which is owned by the API HPA.

## Preconditions

`root-dev` and `album-dev` were Synced/Healthy with automated sync and
`selfHeal=true`. The API image was `sha-b7122b7`, and the API HPA current and
desired replicas were both one. The alternate API tag `sha-4486b3b` was
available with manifest digest shown above.

## Procedure and observations

An initial attempt added a Deployment metadata annotation, then a Pod template
annotation. Argo continued to report the application as Synced and did not
remove either annotation; the Pod-template annotation caused a rollout. Both
annotations were manually removed, the declared API image was preserved, and
the API rollout returned Ready. These annotation attempts did not satisfy the
drift acceptance criterion.

The accepted run used a Git-managed field: `kubectl set image deployment/api`
temporarily selected API tag `sha-4486b3b`. A Deployment watch observed the
changed image and then the automatic return to `sha-b7122b7`. The application
briefly reported OutOfSync, then returned Synced/Healthy with no pending
operation. The HPA remained at one current and desired replica; its
`spec.replicas` was not edited.

## Recovery

The API Deployment image and manifest digest matched Git (`sha-b7122b7`,
`sha256:91b6d71a6db96f6d3108cbe5476b644481334b17a465c3aa79580f0e27b2c263`).
The Deployment rollout completed, HPA current/desired replicas remained 1/1,
and both `root-dev` and `album-dev` were Synced/Healthy with automated sync
enabled and no pending operation.

## Limits

Self-heal was verified for a managed container image field. In this setup,
Argo did not flag the tested metadata annotation changes as drift; those
attempts were manually cleaned up and are not evidence of self-heal.
