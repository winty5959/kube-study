## Purpose and expected behavior

Change the dev-only `THUMB_MEDIUM_PX` setting and verify that the generated
ConfigMap hash changes, API and worker roll out with the new configuration,
and an uploaded test image uses the new medium thumbnail size. Restore the
standard configuration and remove the generated fixture.

## Preconditions

`root-dev` and `album-dev` had automated sync enabled and were Synced/Healthy.
The dev overlay set `THUMB_MEDIUM_PX=800`; its generated ConfigMap was
`album-config-d9mf45f292`. No production manifest or image tag was changed.

## Procedure and observations

The dev overlay temporarily merged `THUMB_MEDIUM_PX=640`. Kustomize rendered
the new value and hash `album-config-m8tf4tm87m`. Argo ran the PreSync migration,
then replaced both API and worker Pods. Both workloads referenced the new
ConfigMap hash and became Ready.

The automatic PostSync smoke uploaded a generated PNG, observed it reach
`DONE`, and fetched the small `200x100` WebP. The medium WebP was `640x320`.
The smoke Job then failed its fixed `800x400` medium-size assertion. This
failure is recorded as observed; the changed output proves the requested
configuration took effect.

## Recovery

The generated smoke photo was deleted through the API (`204`); its subsequent
lookup returned `404`. Git reverted the temporary dev-only value in commit
`ad0621d`. Argo returned the ConfigMap to `album-config-d9mf45f292` with value
`800`; the API and worker both used that hash and were Ready. The follow-up
PostSync smoke succeeded, `root-dev` and `album-dev` were Synced/Healthy with
no pending operation, and both Redis job lists had length zero.

## Limits

This exercised a dev-only ConfigMap rollout with one generated image. The
PostSync smoke script retains its standard `800x400` expectation; a deliberate
setting change causes that check to fail until the normal configuration is
restored. No production sync or external release was attempted.
