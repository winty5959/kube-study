## Purpose and expected behavior

Stop the PostgreSQL StatefulSet temporarily. The API readiness endpoint should
report the unavailable dependency while liveness remains healthy. Restoring
PostgreSQL should restore readiness without losing the bound data volume.

## Preconditions

`root-dev` and `album-dev` automated sync were paused to prevent reconciliation
from changing the experiment. The PostgreSQL PVC was `Bound`, requested `2Gi`,
and referenced volume `pvc-54b047b5-92a7-4d02-943f-0526f51bf45e` in
`album-standard-ssd-retain`. No user write was issued during the outage.

## Procedure and observations

The experiment scaled only `statefulset/postgres` from one replica to zero.
While the database Pod was absent, repeated direct API probes showed
`/healthz=200` and `/readyz=503`. The readiness body reported
`postgres=error: PoolTimeout`, `redis=ok`, and `s3=ok`. On sample 6, the API Pod
was still `Running`, had zero container restarts, and its Kubernetes Ready
condition had transitioned to `False`.

| Time KST | Observation | Evidence |
|---|---|---|
| 02:35 (approx.) | PostgreSQL replicas set to zero; PVC remained Bound | `kubectl scale statefulset postgres --replicas=0`; `kubectl get pvc data-postgres-0` |
| 02:35-02:36 (approx.) | `/healthz=200`, `/readyz=503`; API Ready=False, restarts=0 | Direct probes and API Pod conditions; dependency checks showed only PostgreSQL unavailable |
| 02:36 (approx.) | PostgreSQL returned to one replica; `/readyz=200` with all three dependencies `ok` | StatefulSet Ready; direct readiness response |

## Recovery

PostgreSQL returned to one Ready replica. `/healthz` and `/readyz` returned
HTTP 200, all readiness checks were `ok`, and the API Pod returned to Ready
without a restart. The PostgreSQL PVC remained `Bound` to the same volume with
the same storage class and capacity. `root-dev` and `album-dev` automated sync
were restored; both Applications were Synced/Healthy with no pending operation.

## Limits

This tests a PostgreSQL StatefulSet outage in the dev cluster. It does not test
database corruption, network partition, or failover to a second database.
