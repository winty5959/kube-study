## Purpose and expected behavior

An API source push should run API lint/tests, build the AKS API image, scan and
publish it, promote only its dev tag, and let AKS Argo CD deploy the image.
K3S image repositories and overlays must remain outside that promotion.

## Preconditions

The A8 CI run was a GitHub Actions `push` event for the AKS application commit.
The acceptance evidence is the actual successful API-only run and its observed
AKS dev deployment, recorded during A8; this experiment does not trigger a
second build solely to repeat the same case.

## Procedure and observations

GitHub Actions run `38861459807`, workflow `Build and publish AKS album images`,
completed successfully. The API matrix job ran Python lint/tests, AKS image and
release helper tests, image build, Trivy scan, GHCR push, and dev tag promotion.
For worker, frontend, and MinIO, Python/frontend tests, Docker build, and image
push were skipped. The API was promoted as `sha-b7122b7`.

The A8 live AKS verification recorded `X-App-Version=sha-b7122b7`, a successful
PreSync migration, successful PostSync smoke, and `album-dev` Synced/Healthy.
The final checks included generated upload to DONE, thumbnail and original
reads, API delete, and a post-delete 404. K3S image repositories and overlays
were not changed by this run.

## Recovery

The run promoted the API tag that remains in the AKS dev Git declaration. The
AKS app and its data services were Synced/Healthy after smoke. No generated
smoke fixture remained. There was no K3S promotion to revert.

## Limits

This reuses the API-only run performed during A8 rather than a new A13 build.
It proves this push path and live deployment, not every API-only commit or
failure/retry path. Release promotion is covered separately by A12/E-13.
